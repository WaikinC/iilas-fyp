# Parcel live camera interface and recovery

Implements the camera/client portion of the existing live-sessions design; full photo/live quality goal is unchanged. Trusted server and independent review/emulator gates must pass before the application composer is connected. Pure adapter/component fixtures may be developed in parallel using external doubles.

## Staff flow

Keep existing file and manual-camera photo workflows. Offer a separate Open live camera action only for currently eligible Parcel Image stage/roles. Manual photo and live preview are mutually exclusive. Preview opens the device without transmitting frames. Show before explicit Start live analysis: sampled JPEG images will leave this device, at most12samples/120seconds/1MiB/960px each, retained with the shipment and readable by Approved shared staff; no continuous video/audio or automatic training. Explain visible faces only, human review and no accepted model currently. Policy limits are not promised FPS/latency/accuracy.

Explicit Start creates a trusted session via the verified controller/client. Server Unavailable creates no frame upload and stops sampling; never display Normal. Show session/frame IDs, shipment/stage, state, safe reason, attempted/completed/dropped counts, monotonic result age and Current/Historical distinction. Only controller-confirmed fresh current-generation results may display Current; never reconstruct freshness after reload or from device wall clock. Model provenance/confidence is shown only from a strict server frame DTO, explicitly uncalibrated with human review required. No session-level condition aggregation or existing photo dashboard projection.

Stop, close, hidden/pagehide, track ended, navigation or actor/role/approval/shipment/stage context changes synchronously fence the controller and release media tracks. Abort does not guarantee already transmitted work was cancelled. Pending raw calls/encoding and unacknowledged server stop must block replacement. Reopening/starting is explicit, not an automatic retry. After a transport ambiguity, show Check saved session/Stop saved session; preserve original IDs, never allocate replacement operations silently. Read-only staff can inspect authorised history but cannot start/retain frames; existing shared role/stage matrix remains authoritative.

## Client adapter

Create `lib/parcelLiveClient.js` and declarations, independent of React/Firebase. Inject same-tab sessionStorage, immutable context `{scopeId,actorUid,shipmentId,stage}`, command function, UUID factory and optional change callback. It uses existing exact seven server commands and strict `toPublicParcelLiveSession/Frame`. Expose controller-compatible open/submit/close, a guarded capture(work) wrapper, pending/recover/stopSaved/review helpers and safe read-only snapshot as appropriate; document exact interfaces before consumers. No DOM/media ownership inside this adapter.

Persist exactly minimal recovery data: scopeId,actorUid,shipmentId,original stage,operationId, sessionId|null, blockedSessionId|null and frameId|null. Stage is retained to replay the original start command after dispatch; never reconstruct from current lifecycle. No bytes/blob/base64/hash/dimensions/timestamp/token/config/model/result storage. Key by scope+actor (one pending session across shipments). Strictly validate storage; malformed/unwritable recovery storage blocks NEW work with a fixed message rather than clearing it and replacing IDs. Server actor lock still protects lost/cleared browser storage.

Write start operation before sending. Matching recovery with unknown session replays the SAME start operation/shipment/original stage; known session resolves only. Busy stores its fixed blockedSessionId and does not become an Open session or automatically stop another tab. Its blocker may belong to a different shipment; validate same actor/scope/session identity and show that server binding. Terminal acknowledgement may clear only the matching original intent. A Blocked operation remains immutable on the server; a subsequent Start is a separately explicit new UUID after reconciliation.

Before reservation, persist frameId. Hash/encode the captured Blob in memory and reserve exact bytes/dimensions/SHA/client declaration; then analyse same frame with canonical base64. No automatic reservation/analysis replay, new frame or new session after uncertain transport. Reserved/Running/unknown -> stop sampling and expose explicit resolve; Cancelled -> controller Stale/null. Never upload if signal/context stopped between any awaited step or external callback. `close` resolves void only after authoritative terminal stop/expiry, otherwise rejects and retains IDs; actual controller blocks restart. A storage write failure after network send retains the original start operation for replay.

Module-local WeakMap keyed by the provided storage object and actor/scope coordinates tracks actual unsettled open/capture/submit plus control cleanup across adapter/component replacements. NEW work is blocked until old raw promises/encoding and stop/reconciliation settle; do not hide a pending request using Promise.race. Capture wrapper accounts for actual toBlob settlement. Cleanup/resolve controls can run while old frame work is pending, but cannot grant replacement permission. Fencing must protect intent writes/clears from stale responses, including when context changes away then back. Do not persist a UI result or current flag.

Sibling-panel clarification from actual Operations review: multiple shipment panels can remain mounted together. Promise/control ownership, listeners and the eight-field recovery intent stay shared by actor/scope, while replacement-generation fences are scoped to shipment plus original stage. A new instance in the same context invalidates its predecessor; mounting an unrelated idle history panel must not invalidate the active camera. Dispose/context changes still fence their actual predecessor, and all contexts retain shared pending-work exclusion and exact intent compare-before-write/clear. Notify replacement observers when old actual work settles so explicit actions can recover without requiring another remount.
