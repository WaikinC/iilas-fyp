## Input and result contracts

The experiment command accepts only operationId plus scenario containing quantityOnHand, reservedQuantity, reorderLevel, movementFrequency, adjustmentCount and daysSinceReplenishment. These are six entries: three balance facts, two counts and receipt age; their derived six model predictors replace on-hand/reorder facts with available/reorder distance. No IDs, labels, model paths, model versions, scope, actor, timestamps, training flags, origin or approval fields come from the client.

Quantities/counts are strict finite integral numbers, quantityOnHand/reservedQuantity/reorderLevel0..1,000,000, reserved<=on-hand, movementFrequency0..2,000, adjustmentCount0..movementFrequency. Receipt age is a finite number0..36,500days, allowing fractional days. Reject booleans, strings masquerading as numbers, NaN/Infinity, extra/missing fields and invalid units. Reorder distance may be negative. The wide software bounds are not a claim that the model is validated at their extremes; label out-of-development-range features visibly using ranges computed from development observations only.

Feature order is available_quantity,reserved_quantity,movement_frequency,reorder_distance,adjustment_count,days_since_replenishment. Class order is Normal,Reorder Risk,Critical Stock Risk. The service returns a closed schema with request ID, input digest, method/version, class order, selected RF model hash, serving-manifest hash, source dataset/development/evaluation identities, label, three finite probabilities summing to1, model inference/total time and fixed experimental provenance. Backend recomputes the derived inputs/digest and validates exact correlation, class order, probabilities, chosen label, model/manifest identity, integer/finite timing bounds and false approval fields before persistence. An unapproved/unknown/mixed result never becomes a Normal fallback.

Provenance includes evaluationKind=synthetic-stock-prototype, origin=simulated-manual, evaluationOnly=true, operationally_approved=false, independentAccuracyValidated=false, acceptanceSha256=null, humanReviewRequired=true. These names are fixed by this design; they cannot be overridden by request/environment result fields. The selected classifier remains RF; DT stays the offline comparison and is not promoted because its held-out score is higher.
