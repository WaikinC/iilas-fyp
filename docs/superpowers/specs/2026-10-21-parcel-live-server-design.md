# Trusted parcel live-session boundary

Status: prospective server contract for Task 2 of `../plans/2026-10-21-parcel-live-sessions.md`; no handler/rules or admission change is implemented by this document. Read the parent live-sessions design, existing photo/access/stage contracts and full goal first.

## Retention and distinct admission

Use a separate immutable `parcel-live/{scope}/{sessionId}/{frameId}` JPEG namespace for at most twelve admitted samples of at most 1 MiB each per session. Exact samples are retained with their session/frame record for later authorised visual review, like existing shipment evidence; no automatic deletion is implemented. State this explicitly before Start: selected sampled images leave the device and are retained, and all Approved staff in the fixed shared scope can view them; no continuous video/audio is recorded, and images are not automatically training data. Camera preview alone transmits nothing. No automatic upload before a trusted accepted Open session and reserved frame slot. Preview uses authenticated SDK bytes/object URLs with cleanup, never a tokenised public download URL.

The server-owned `parcelLiveAcceptance` starts null. A valid descriptor requires intendedUse `sampled-live`, the exact policy version/hash, primary MobileNetV2 checkpoint/selection/evaluation/acceptance digests, preprocessing/contrast and Normal/Damaged class order. Neither `parcelAcceptance` (registered-photo), request flags, environment flags nor Python's claimed approval can supply it. A missing live pin or service produces a durable Unavailable session before reservation, Storage or HTTP. Python live admission remains a distinct required integration and must stay closed until scientific and physical-device acceptance; positive software fixtures are external doubles only.

Do not modify existing evidence records or v1/v2 canonical integrity, generic photo registration, photo analyses, stock/handover or existing dashboard projections for live frames. Separate public session/frame records link shipment/stage/actor/time/model/image identity. Live outcomes are never automatically counted as current accepted photo evidence.

## Public commands

All commands use existing trusted `command` dispatch and server-derived actor/fixed scope. Inputs are exact own-property allowlists, valid canonical IDs, no coercion. UUID IDs must be lowercase v4. Shipment IDs retain existing safe project ID syntax.

1. `startParcelLiveSession({shipmentId,stage,operationId})`: atomically creates one immutable start receipt keyed by SHA(scope,actor,operationId), a server UUID session and a public session record. Matching replay returns the same record before NEW-work stage permissions; changed input with same operation rejects. A private actor lock keyed by SHA(scope,actor) permits at most one Open session for that actor across all tabs/shipments. A new operation meeting an existing lock, including an elapsed lock, stores an immutable Blocked receipt and returns Busy with the fixed blocking session ID; replay remains Busy after that session closes, never opens a replacement. Explicitly resolve/stop the blocker before a separately explicit new operation. All lock release paths compare scope/actor/session/startReceipt/nonce/generation/expiry, never only session ID; predecessor cleanup cannot release a successor. Unavailable sessions acquire no active lock. Current Approved active staff and stage matrix are required for NEW work. Initial state is Open only with live pin/service configured, otherwise Unavailable. The open snapshot binds config version/scope, creator account role/status/active/version, shipment owner/status/version, and transport plan presence/owner/version/driver. Server start time fixes expiry at +120000 ms; returned policy is exact version/hash/limits, never caller-supplied.
2. `reserveParcelLiveFrame({sessionId,frameId,sequence,bytes,sha256,width,height,capturedAtClient})`: caller creates UUID frameId before any network attempt. It is the immutable frame operation ID; sequence must equal the server's next integer (1..12). JPEG only; bytes 1..1048576, positive integer dimensions with long edge <=960, canonical ISO client time bounded five minutes ahead. Server records the declaration but trusts neither device clock nor declared content. Matching immutable receipt replay returns that frame before NEW-work checks; altered bindings reject. New reservations require creator identity, current authority/snapshots, Open session, unexpired lifetime, same live pin/policy, no in-flight frame, count <12 and >=5000 ms since prior reservation. The count increments on reservation, including later failed/expired frames; no replacements. First frame has no cadence delay. Set slot and private frame nonce/lease, public state Reserved; frame lease expires no later than min(reserve+60000,session expiry). Return a safe reservation DTO, never a client upload grant or service URL/config/key.
3. `analyseParcelLiveFrame({sessionId,frameId,jpegBase64})`: validate encoded string length <=1398104 and canonical base64 shape before decode; decoded bytes <=1MiB. First claim atomically changes Reserved -> Running before external I/O and saves a separate immutable digest of canonical sessionId/frameId/base64 input (never the raw string). Exact Running/terminal replay first compares that ingest digest, rejecting changed bytes, and never executes again; resolution handles lost responses. Validate creator, current context, open/unexpired session, exact slot/nonce/frame receipt and acceptance before decoding/accessing image bytes. Actual SHA/length/JPEG signature/dimensions must match the reservation. The server writes the verified exact buffer create-only with generation precondition0 to the immutable live namespace under a10s deadline; no client Storage upload. Bind returned object generation/metageneration before inference; missing, conflicting or ambiguous object write fails closed without replacement inference. Python request <=30s including a <=16KiB body, abortable; total trusted handler deadline <=50s and never beyond frame/session expiry, inside Function60s. Final transaction rechecks all original coordinates, exact config/creator/shipment/plan/pin/policy snapshots, session Open generation and slot, image hash/version and final authority clock after reads. Only then save Predicted/Abstained; no legacy prediction projection. All external raw errors map to a fixed safe reason set. Raw JPEG/base64 must never be persisted to Firestore, logs, sessionStorage or public DTOs; the one retained Storage object is the explicit evidence copy. Stop/expiry may race a pending or ambiguous create-only write and leave that single object retained: terminal inference remains null/immutable, retention/generation explicitly unknown when unverified, never a false claim that no bytes were saved. No automatic object-write/inference retry or orphan-deletion feature.
4. `resolveParcelLiveSession({sessionId})` and `resolveParcelLiveFrame({sessionId,frameId})`: Approved shared historical reads; atomically expire elapsed Open/Reserved/Running records and release only matching owned slot. No acquisition/inference retries, no resurrection. Parent expiry terminalises its own matching in-flight frame to Expired without publishing output. Resolve must not require the old creator's current capture rights to show historical null-safe results.
5. `stopParcelLiveSession({sessionId})`: creator or current Admin/Manager, Approved fixed scope; terminal idempotence before new capture checks. Atomically Open -> Stopped, increment generation, cancel matching Reserved/Running frame with null label and clear exact slot. Same transaction document conflicts order stop versus finalise; already committed results remain historical and cannot become current after stop. Explicit stop need not require unchanged shipment/assignment; loss of capture rights must not prevent authorised cleanup. Server-internal null cleanup can expire/cancel the original coordinates after creator revocation, never restore business authority. A lost stop acknowledgement requires explicit same-session resolve/stop recovery before the browser starts a replacement session. Expiry is the fallback for closed/hidden/unreachable clients, not a guarantee that remote compute was prevented.
6. `reviewParcelLiveFrame({sessionId,frameId,version,decision,notes})`: current Admin/Manager, exact Pending version and immutable retained image/result linkage. Predicted permits Accepted/Rejected; Abstained permits Reviewed notes while preserving null label. Notes3..240. Never create training labels, photo projections or infer hidden/internal condition. Retained bytes must remain accessible for meaningful review; hash-only/missing/corrupt images cannot be reviewed Accepted. Before storage access, pre-authorise review; bounded-read and reverify the exact recorded object generation/metageneration/hash/length/type/dimensions outside the transaction, then recheck current reviewer authority and unchanged frame/result/image/review versions in the final transaction. Never accept merely because an object with that path exists.

## Records and rules

Public `parcelLiveSessions`: ownerId/sessionId/actorUid/operationId/shipmentId/stage, exact policy, safe selected model or null, state Open/Stopped/Unavailable/Expired/Stale, server createdAt/expiresAt/stoppedAt, version/generation, reserved/completed counts, inFlightFrameId or null, last reservation time, safe reason. The in-flight slot is not a display-freshness field. Historical latest results are queried separately; no stored current=true or client wall-clock reconstruction. Every terminal session invalidates current display. No mutable client writes.

Public `parcelLiveFrames`: ownerId/sessionId/frameId/sequence/actorUid/shipmentId/stage, JPEG hash/bytes/dimensions/client capture declaration, server reservedAt/expiresAt/completedAt, state Reserved/Running/Predicted/Abstained/Unavailable/Failed/Stale/Expired/Cancelled, null-safe label/probabilities/confidence, uncalibrated meaning, model lineage/service request/processing times and retained image identity. Explicit review fields are humanReviewRequired, reviewStatus, reviewNotes, reviewedBy, reviewedAt and version. Predicted/Abstained begin humanReviewRequired=true, reviewStatus=Pending, notes/reviewer/time=null; their allowed terminal decisions are respectively Accepted/Rejected or Reviewed, with required notes/current reviewer/server time. Review never changes the inferred condition or probabilities. Other frame states carry no inferred condition and reviewStatus=NotApplicable, reviewNotes/reviewedBy/reviewedAt=null; manual inspection does not turn them into Normal. Retained identity binds server-verified object generation/metageneration (canonical decimal strings), hash/length/type/dimensions; reservation fields remain declarations until bounded verification. DTO allowlists keep private paths/nonce/snapshots/service settings/exceptions out; the authorised image adapter constructs the deterministic namespace from validated public coordinates. Identity and results immutable except versioned review fields. Frame/receipt keys are SHA256 of canonical scope+session+frame UUID coordinates and are create-only; the same UUID in a different session cannot overwrite/replay an unrelated frame. Reject any mismatched existing coordinates.

Private start/frame receipts and actor locks contain canonical input digest, actor/scope/session/frame coordinates, nonce/lease/generation and original authority/model snapshots. All client reads/lists/writes denied. Public collections permit only existing Approved shared fixed-scope reads and no direct writes. Live Storage creates/updates/deletes deny all clients; only the trusted command writes a verified reserved frame under current authority and budget. Storage reads require same Approved fixed scope using only the current user and system/config documents (at most two distinct Firestore reads). No unconstrained arbitrary file IDs: reservation must exist first. Object create-only preconditions preserve immutability even under worker duplication.

This server ingestion replaces the initially proposed client live Storage-create policy. Firebase documents a maximum of two Firestore document accesses per Storage Rules request: [official rule limits](https://firebase.google.com/docs/rules/rules-behavior#security_rules_limits_2). Checking current account/config/shipment/plan/session/frame exceeds that limit; emulator success cannot prove deployed feasibility. Do not denormalise authority grants across unrelated business commands to evade the limit. The existing photo Storage-create policy also accesses more than two distinct documents; record a production-feasibility issue for that existing path, without silently treating its prior local emulator checks as deployment acceptance. Production remains outside authorisation.

Preserve all receipt identities across timeout/reload; no automatic new operation or replacement on ambiguous result. Browser keeps only minimal IDs in same-tab sessionStorage, no bytes/results/config/tokens. New session after a local timeout is blocked until authoritative old-session reconciliation. On reload, all old frames are historical; a reset monotonic origin or device wall-clock cannot reconstruct current freshness. Reconcile/close the old session before an explicitly new one. The Task 1 controller adapter must map server Busy into safe non-start/recovery UI, preserving its original start operation and fixed blocker, never treating Busy as an Open session. Reserved/Running/unknown frame responses preserve the same frame identity and stop the loop, with explicit resolve recovery; Cancelled maps to terminal Stale/null for the controller. Close resolves only after server terminal acknowledgement; a lost stop acknowledgement requires explicit resolve/stop using saved IDs before replacing the permanently restart-blocked controller. Client cadence additionally waits at least5000ms after prior submission completes, avoiding encoding-time jitter against server reservation cadence. A browser UUID cannot grant sequence, ownership, role, acceptance or budget.

Positive worker tests only with external accepted-live doubles. Sequential original smoke/QA/shared/access/stage/photo regressions, build/lint/security and actual app desktop/mobile camera fixtures required. No physical-camera or model acceptance claim follows from mocks.

This contract deliberately retains per-frame evidence and review, meeting FR-11 traceability rather than a hash-only diagnostic shortcut. All sealed research sources/models and147reserved pixels stay untouched.
