# Parcel live sampled-frame sessions

Status: implementation design for the authorised photo/live parcel goal. No live model or physical-camera acceptance is established. The first implementation unit is the independently testable foreground session controller; the server and application integration remain required.

## Purpose and choice

Choong's FR-10/FR-11 and sampled-camera loop (Figures 3.9, 4.10, 4.13–4.14, 4.23) require ongoing sampled analysis, not repeated manual capture. See `../../PARCEL_CAMERA_SCOPE_2026-10-20.md`. Keep existing photo requests intact. A foreground browser controller samples through a trusted session/frame adapter, and accepts only results belonging to its current session and frame. It does not decide scientific acceptance or grant access.

Alternatives: a background continuous video service introduces new deployment/device ownership and retention beyond the current browser workflow; a timer wrapping photo commands misuses registered-photo acceptance and has no server cancellation boundary. Use bounded foreground sampled sessions with a distinct server contract. No raw continuous video recording, automatic training, damage responsibility or automatic stock/delivery changes.

## Foreground policy

Fixed engineering limits for this first implementation, not measured performance promises: maximum 120,000 ms per session, 12 attempted frames, minimum 5,000 ms between capture starts, one capture/submission in flight, zero queued frames. Also wait at least 5,000 ms after a completed submission before the next capture: this conservative cooldown prevents variable encoding latency from violating the server reservation cadence. JPEG encoder adapter must enforce maximum long edge 960 pixels and at most 1 MiB per frame. A result at age 15,000 ms or later is historical/stale and never current. Each capture/submission has a combined 60,000 ms local deadline. No retries or replacement frames after an ambiguous submission. Stop on transport/capture/protocol failure, unavailable service/model, visibility loss, track end, navigation or authority/context change. Closing the browser cannot guarantee cancellation of already transmitted server work.

The server will independently enforce its own lifetime, frame count, cadence and claim/stop fences; client timers and AbortSignal are not authority. Stop changes local generation synchronously and aborts the active adapter signal. A late result from an old generation cannot become current, restart sampling or affect a later session. A transport that ignores abort remains outstanding: restarting on the same controller is rejected until that operation settles. This bounds actual outstanding work rather than merely forgetting a promise on timeout.

## Controller interface (Task 1)

Create `lib/parcelLiveSession.js` and matching `.d.ts`, no React/Firebase dependency. Export frozen `PARCEL_LIVE_LIMITS` and `createParcelLiveSession(options)`.

Options:
- `open({operationId, signal}) -> Promise<{sessionId,state:'Open'|'Unavailable'}>`; the adapter owns actor/scope/shipment/stage context and durable start recovery. It must resolve a lost first response by the SAME operationId, never create a replacement automatically.
- `capture({sessionId,frameId,sequence,signal}) -> Promise<{payload:unknown,bytes:number,capturedAtClient:string}>`; called only once per selected frame, never save this payload in controller state/events.
- `submit({sessionId,frameId,sequence,bytes,capturedAtClient,payload,signal}) -> Promise<{sessionId,frameId,sequence,state:'Predicted'|'Abstained'|'Unavailable'|'Failed'|'Stale'|'Expired',label:'Normal'|'Damaged'|null}>`. Additional backend DTO fields may be carried through only by the adapter; the controller emits the bounded allowlisted identity/state/label fields. Predicted requires a known label; every other state requires null. Session/frame IDs and sequence must match exactly. Predicted/Abstained may continue sampling even when locally age-stale (historical only); Unavailable/Failed/Stale/Expired stop sampling. Server Reserved/Running/unknown responses are not terminal: the adapter preserves the same frame operation and stops with safe submit-failed rather than allocating another frame, exposing explicit outcome recovery separately. External Cancelled maps to Stale/null in the adapter and stops the loop.
- `close({sessionId,reason}) -> Promise<void>` best-effort one call per known opened session, independent of an aborted frame signal; the server adapter preserves/reconciles ambiguous stop. It resolves only after authoritative terminal stop/expiry is known; rejection means unacknowledged. Safe reasons are explicit enum values defined by declarations, never raw exception messages. Closing/recovering the server session is a prerequisite of allowing another real application session. A rejected close permanently blocks restart on that controller; explicit recovery uses the adapter's durable IDs to resolve/stop the old server session, then creates a replacement controller only after authoritative terminal acknowledgement. Clearing/replacing the controller cannot bypass this adapter requirement or the server actor lock.
- `onEvent(event)` receives safe state/result counters and reason codes only, never payload/error strings/tokens. Event listener exceptions cannot break cleanup.
- injected `now()` monotonic milliseconds (default performance.now), `setTimer(callback,ms)`/`clearTimer(handle)` (default timers), `createId()` UUIDv4 (default crypto.randomUUID).

Returned controller: `start():Promise<void>`, `stop(reason='user-stop'):void`, `snapshot():Snapshot`, `dispose():void`. Start is explicit, idempotently rejects/ignores overlapping invocation without opening a new session. A completed or failed start requires another explicit start. Dispose is permanent. State is Idle, Starting, Running, Stopped or Unavailable. Snapshot contains sessionId or null, attempted, completed, dropped, lastResult or null, reason or null, current boolean and resultAgeMs or null. Dropped counts cadence slots while a frame is busy; it never counts these as captured/independent observations. Result age uses monotonic capture-start time; capturedAtClient is an untrusted ISO declaration. Session start time is immediately before opening (open latency counts toward the lifetime).

Events: snapshot updates `type:'state'`, allowlisted result `type:'result'`, and `type:'closed'` with sessionId/reason and acknowledged boolean. A fresh result automatically loses current status exactly at the age boundary even if no later frame arrives. Starting a newer frame does not make an older frame current again. Every terminal session clears current status; historical lastResult remains labelled historical. No automated session-level Normal/Damaged aggregation: one frame only describes visible packaging.

Protocol input validation rejects malformed/missing IDs, noninteger/over-limit bytes, noncanonical client timestamps, unexpected states and mismatched/null-label violations. Never expose raw adapter errors. Deadline/invalid result/capture failure stop sampling with a fixed safe reason, abort and request close. A late open that resolves after stop/dispose must be closed using its returned session ID; it cannot activate the camera loop. Starting a new session must wait for old open/capture/submit and close work to settle. There is no unbounded map/history; retain at most one result and counters.

## Trusted server and application work (subsequent tasks)

Before connection, specify and implement durable scoped session start/resolve/stop and frame claim/finalise identities, immutable operation receipts, server budgets, authorised stage/assignment snapshots, and stop/expiry generation fencing. Use separate live intended-use acceptance; the existing `registered-photo` pin must not authorise live inference. Null live acceptance must be explicit Unavailable before frame bytes/model I/O. Decide image retention and provenance before any automatic Storage upload; do not retrofit arbitrary live metadata into existing v1/v2 integrity records.

The camera component must own its media tracks, downscale/encode a single frame under these bounds, stop on hidden/pagehide/track end/context change and display current versus historical results, result age, counts and safe failures. Opening camera preview is separate from explicitly starting transmission. All planned transmission/retention must be explained before Start live analysis. Reuse current stage matrix and remount fencing; preserve manual-photo/file workflows. Live results must not enter current-photo dashboard counts accidentally.
