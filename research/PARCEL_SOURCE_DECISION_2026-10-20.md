# Parcel data decision and implementation route — 20 October 2026

## Decision

**Proceed with the existing Parcel3D review as a separate synthetic baseline; do not add either new source to training yet.** Both new acquisitions failed to establish a suitable trusted real-parcel cohort. Parcel3D itself still requires human label/family decisions before any training. No existing synthetic result establishes real-camera reliability.

Roboflow's Damaged Intact Box Dataset v1 was acquired after the user completed normal sign-in on MSI. All 581 images decode, but visual screening of 96 evenly spaced examples (48 per source class) found stock watermarks, cartoons, mockups, food/medicine packaging and apparent label errors. Three exported images were also inspected separately: R032 is an ordinary open carton labelled damaged; R075 explicitly shows a box mockup; R079 is a visually relevant shipping carton but lacks verified original provenance and physical identity. These are audit observations, not human condition decisions. Hold the source; only a subsequently verified subset could be reconsidered. Do not use the entire collection as ground truth or claim it improves accuracy.

The ZIP is 20,893,744 bytes; 583 extracted files total 20,731,720 bytes. Images: 256 damaged / 325 intact, all 640x640. Source split: 412 train / 113 valid / 56 test. ZIP CRC and local SHA-256 manifest pass; no publisher checksum was supplied, so this is local integrity verification. No exact encoded/decoded duplicate sets; five perceptual similarity pairs include three across source splits. Flags require review and do not by themselves prove shared identity. Physical parcel groups remain unknown. Originals, archive, hashes, 581-row blank review ledger and screen evidence are ignored under `datasets/roboflow-parcel-v1-20261020/`.

No newly accepted real-parcel cohort exists yet. More images do not guarantee higher precision: irrelevant packaging, ambiguous labels and repeated parcels can inflate a score without improving IILAS.

## How implementation will work

1. **Intake and label review.** Export a fixed dataset version locally into ignored research storage. Preserve publisher metadata, attribution, file hashes and original labels. Decode images; detect exact and perceptual duplicates; quarantine food packaging, unrelated objects, unreadable views and unclear reuse provenance. Record IILAS visible-condition labels independently: Normal, Damaged, or an Uncertain review hold. A source label or assistant suggestion is not a human-approved annotation.
2. **Resolve parcel families before splitting.** Keep the same physical box, repeated web image, derived crop and related capture session in one group. Filename similarity alone does not prove identity. Hold unresolved families out of independent-parcel evaluation. Freeze eligibility and group-based train/validation/test membership before fitting; retain a separate synthetic benchmark.
3. **Train a bounded research classifier.** Start with ImageNet-pretrained MobileNetV2; compare EfficientNetB0 under the same frozen protocol. Use shared RGB/orientation/resize preprocessing at 224 pixels, training-only augmentation, a frozen-backbone stage and controlled fine-tuning. Choose settings on validation only. Implement a separate runner with measured RAM preflight, explicit process/time/epoch limits and versioned research outputs; do not invoke the existing training CLI with its default active-model output.
4. **Evaluate once on held-out groups.** Freeze model, threshold and image/session rules before opening final scores. Save predictions and hashes, then report confusion matrix, Damaged precision/recall/F1, macro F1 and accuracy with independent group denominators. A small or provenance-uncertain public test is exploratory evidence, not proof of deployment readiness. No promised accuracy target is implied.
5. **Integrate photo inference.** A staff member attaches a parcel photo to a shipment and inspection stage. The trusted backend calls the Python model service and records image hash, model version, result and review status. Blurred, incomplete, unsupported or failed analysis must trigger review rather than silently becoming Normal. Verify model-file hashes, consistent preprocessing and cached model loading before acceptance.
6. **Implement report-backed live camera analysis.** Sample frames through the same classifier using permission/start/stop controls, a bounded queue and stale-result handling. Guided capture can request front/back/left/right/top/bottom views. This is multi-view inspection; a 3D reconstruction is not required. Do not majority-vote away a defect visible on one face. Develop and validate session aggregation before final evaluation, then test camera latency, interruptions and memory separately.

No step has permission to infer hidden damage or certify contents. A Normal frame means no visible external damage in an adequate view; incomplete coverage must remain explicit. Multi-view capture and live performance cannot be validated from arbitrary still images alone.

## Remaining gap and next deliverable

The new exports and file audits are complete. The immediate next core task is to finish the existing Parcel3D human/family review and prepare the bounded vision runner against synthetic test fixtures, before any real fit. For Roboflow, resolving original provenance and reviewing all relevant originals/families is required before admitting any subset. No approved independent real-parcel count exists. Do not relabel unrelated packaging to meet a count or fit a model merely because images were downloaded.

For final IILAS validation, collect an independently held-out set of actual assembled parcels under the intended cameras, lighting and handling workflow when the user is ready to extend the current public-only constraint. Track physical parcel IDs and before/after states together, label visible damage with reviewers, and include multiple sides and live sessions. Public data currently does not fill this gap.

Current task status: two local acquisitions/audits and documentation complete; both sources excluded or on hold for primary training. No model trained, activated or deployed; no application behavior changed. Other AI models and additional features remain deferred.
