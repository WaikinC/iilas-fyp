# Parcel live interface software fixture

Run `node scripts/parcel-live-ui-qa.mjs` from the application checkout using Node22.13+ within major22, with the existing Vite service already available at literal `http://127.0.0.1:5173`. The runner uses installed Playwright and Edge. Browser launch may require the normal Windows sandbox escalation. It never starts another Vite service or Firebase emulator.

The fixture replaces Firebase modules externally through browser routing and substitutes canvas-generated video for `getUserMedia`. Its generated retained JPEG has honest byte length/SHA-256 metadata. It calls no real callable, Storage or camera. These are source/interface proofs, not live model admission, physical-camera, latency/resource or scientific-quality acceptance. The actual application composer was connected only after trusted handler review and sequential native emulator verification passed. The separate ignored native-app runner exercises real loopback commands/Storage/Auth with disposable exact-ID fixtures and a synthetic camera; it does not open model admission.

`ParcelLiveCamera` takes current `member`, `shipment`, explicit `stage`, controlled `active`, `onOpen`, `onClose` and optional `acquisitionDisabled`. Acquisition-disabled blocks Open/Start and releases a running preview/controller while leaving historical records and recovery controls accessible. Controlled `active=false` also synchronously fences the controller and releases media. `EvidenceUpload` owns one media mode keyed by full authority/shipment/stage identity: manual-camera, file-selection and upload block live acquisition; live preview/analysis blocks manual controls. The live history remains outside the capture-allowed branch so Approved Viewers can inspect shared historical sessions/frames. Its own context key fences role/approval/member/shipment/stage version changes and never automatically reopens after remount. New same-shipment/stage adapter owners fence predecessors; unrelated idle panels coexist. Actual work/control promises and recovery intent remain shared by scope+actor across every panel.

Recovery saves exactly eight identity fields, including the original requested stage, across shipment/stage changes. It stores no frame bytes, hashes, times, models, results or credentials. Recovery commands are explicit; Reserved/Running/unknown outcomes never trigger reservation/analysis replay. Terminal acknowledgement plus actual-promise settlement is required before a replacement.

History reads require the following composite index definitions when the parent integrates them (no cloud operation or index change is performed by this fixture):

- Collection `parcelLiveSessions`, query scope `COLLECTION`, fields `ownerId ASCENDING`, `shipmentId ASCENDING`, `createdAt DESCENDING`; maximum20 sessions per history page for the current scope+shipment.
- Collection `parcelLiveFrames`, query scope `COLLECTION`, fields `ownerId ASCENDING`, `sessionId ASCENDING`, `sequence ASCENDING`; maximum12 frames for an explicitly selected session. Public frame document IDs are checked using asynchronous `parcelLiveFrameKey(ownerId, sessionId, frameId)`.

History is paged explicitly with Older, Newer and Latest. Older uses `startAfter(lastDocument)` plus `limit(20)`; Newer uses `endBefore(firstDocument)` plus `limitToLast(20)`. Document-snapshot cursors preserve Firestore's implicit document-ID tie order for identical timestamps. Only one20-record historical page, its first/last cursor and one request cursor are retained; there is no growing page stack. Empty boundary pages expose an inclusive return cursor and a fixed notice. Failed reads preserve the prior bounded page and offer explicit Latest/retry. Navigation invalidates old callbacks before subscription replacement, and full authority/context remount resets the cursor.

The one selected session's bounded12-frame subscription/review remains open across history-page changes, so paging does not discard an old Pending review or a foreground current frame. While the controller is Running, a separate single-document observer watches its exact session ID and validates scope, actor, shipment and recorded stage. Missing/malformed/terminal records fence the controller immediately even when history shows older pages. This observer retains no additional historical page and unsubscribes/fences callbacks when the owner or watched session changes. History navigation never starts or retries inference.

The synthetic browser fixture covers41sessions with tied timestamps, an oldest Verified retained Pending review, reverse/latest navigation, empty boundaries, failed/held reads and remote stop while viewing older history. The separate focused native runner uses only disposable Unavailable metadata records with the real SDK/emulators; its positive Pending-review proof remains external/synthetic. Neither fixture opens model admission or establishes physical-camera/scientific acceptance.

Retained preview is explicit, authenticated `getMetadata`/`getBlob`, with exact recorded generation/metageneration/type/length checked before and after reading and SHA-256 checked before any object URL. URLs are revoked on close, replacement, unmount and context change. Review is restricted to current Admin/Manager, Verified retained Pending Predicted/Abstained frames, exact version and3..240-character notes. Server authority and immutable linkage remain authoritative.
